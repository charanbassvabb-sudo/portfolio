01 / about

Who I am

I'm Charan Basava, a Computer Science student in Lusaka, Zambia, studying towards a BSc in Computing & Cybersecurity at the University of Greenwich. I build web systems where security is designed in from the schema up, not bolted on afterward.

My dissertation project, CipherVault, is a password manager built on FastAPI with Fernet symmetric encryption. Outside coursework, I've built and deployed Indish — a full production platform for a real two-branch restaurant business, covering the public site, a server-validated reservation flow, an admin dashboard, and a separate branch-aware loyalty program, all wired to WhatsApp for customer notifications.

I care about the parts that don't show up in a screenshot: server-side validation that doesn't trust the client, httpOnly auth cookies instead of localStorage tokens, and databases that stay scoped to the thing they're supposed to own.

Indish — Restaurant & Loyalty Platform
→ indishzambia.com
Live site ↗ Source ↗

A full-stack platform for a real Indian restaurant with two independently-run branches (Lusaka & Kitwe): public site with a 190-dish menu, a mobile-money-backed reservation flow, a staff admin dashboard, and a separate branch-aware loyalty program that talks to it only through deep links — never a shared login or database.

React + Vite + TSExpress + PrismaTanStack Start (SSR)MySQLWhatsApp Cloud APINginx + PM2 · DigitalOcean
  • Nothing client-trusted: the ZMW 100/guest deposit and the rolling 24-hour booking window are both enforced server-side (Zod superRefine), not just in the UI.
  • Two databases, one server: the restaurant backend and the loyalty app each own a separate MySQL database — connected to each other only by pre-filled deep links, so a bug in one can't touch the other's data.
  • Real notifications: confirmed bookings trigger an approved WhatsApp Business template to the customer and a free-text alert to staff via Meta's Cloud API.
  • Auth done properly: admin sessions use JWT in httpOnly cookies (not localStorage), behind rate limiting, Helmet, and CORS scoped to the real origin.
  • Deployed, not demoed: Nginx + PM2 on a DigitalOcean droplet with Let's Encrypt TLS — this is the config actually serving indishzambia.com.
● dissertation project · 2025
CipherVault
Source ↗

A full-stack password manager: register, log in, and store/retrieve/delete credentials that are encrypted at rest with Fernet symmetric encryption, never stored in plaintext. Built as my final-year dissertation for the BSc Computing & Cybersecurity programme at the University of Greenwich.

FastAPIPythonMySQLFernet encryption
  • Encryption at rest: every stored credential is symmetrically encrypted with Fernet before it touches the database — a compromised DB dump alone isn't enough to read passwords.
  • Scoped access: users can only ever retrieve or delete records tied to their own authenticated session.
